# TSC-001 — Remove LEGACY_CAPABILITY_ALIASES

**Tracking ID:** TSC-001
**Status:** DEFERRED
**Created:** 2026-07-15
**Origin:** TSC Resolution TSC-2026-07-15-B
**Owner:** Platform Team

---

## Description

`LEGACY_CAPABILITY_ALIASES` in [`capability-resolver.cjs`](../../electron/chatr-core/kernel/capability-resolver.cjs) is a deprecated migration bridge that normalizes non-canonical capability inputs (e.g., `'search'` → `'DISCOVER'`) to canonical ABI names.

Following the B-01 remediation, the GoalPlanner now emits canonical uppercase capability names. The alias map is no longer necessary for the primary execution path and exists only as a compatibility shim.

---

## Removal Conditions

All three conditions must be satisfied before removal is approved:

- [ ] **Every ABI producer emits canonical capability IDs.** This means every GoalPlanner instance (kernel and any external planners) emits `'DISCOVER'`, `'COMPARE'`, etc. — not `'search'`, `'compare'`, or any alias.
- [ ] **No compatibility tests depend on the alias map.** Architecture Lint must confirm no test fixture or compatibility test passes non-canonical input that relies on alias normalization to succeed.
- [ ] **Architecture Lint rejects lowercase capabilities.** The lint rule that rejects lowercase capability names must be active and enforced in CI before removal.

---

## Implementation Plan (upon approval)

1. Delete the `LEGACY_CAPABILITY_ALIASES` constant from `capability-resolver.cjs`.
2. Remove the alias lookup from `normalizeCapability()`. The function already validates canonical uppercase inputs directly; alias lookup is the only non-canonical path remaining.
3. Update the Architecture Lint configuration to add `LEGACY_CAPABILITY_ALIASES` to the list of forbidden symbols.
4. Run the Platform Milestone B certification suite — all 305 assertions must still pass.
5. Submit for TSC approval as an ADR (minor — ABI purity improvement, no contract change).

---

## Risk

**Low.** The alias map is already marked `@deprecated`. No kernel production path relies on it after B-01. The only risk is external planners that were not updated to emit canonical names — those are caught by the removal conditions above.
