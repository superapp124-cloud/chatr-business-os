## 1. Purpose

This document defines the canonical, closed event vocabulary for the CHATR Intent OS. All communication between runtimes and between runtimes and the kernel occurs exclusively via events on the kernel event bus. No runtime may invent, emit, or consume events outside this vocabulary. The vocabulary is closed: additions require a MINOR or MAJOR version increment of this document.

---

## 2. Envelope Schema

Every event emitted on the kernel bus MUST conform to the following envelope. Events that do not conform MUST be rejected by the bus with `EVENT_SCHEMA_VIOLATION`.

```json
{
  "event_id": "string (UUID v4, required, globally unique)",
  "event_type": "string (namespace.verb format, required, must be in the canonical vocabulary §3)",
  "version": "string (semver, required, version of this event schema)",
  "timestamp": "string (ISO8601 UTC, required, time the event was emitted)",
  "source_runtime": "string (required, one of: ObservationRuntime | StewardshipRuntime | ExecutionRuntime | VerificationRuntime | LearningRuntime | Kernel)",
  "intent_id": "string (UUID v4 or null; null for system-level events with no associated intent)",
  "correlation_id": "string (UUID v4, required; identifies the chain of events for a single user interaction)",
  "causation_id": "string (UUID v4 or null; the event_id of the event that directly caused this event)",
  "payload": "object (required; content is event-type specific; may be empty object {})"
}
```

### Envelope Field Rules

| Field            | Rule                                                                                               |
|------------------|----------------------------------------------------------------------------------------------------|
| `event_id`       | Generated by the emitting runtime. Must be unique across the entire event store. Never reused.     |
| `event_type`     | Must exactly match one of the strings defined in §3. Case-sensitive.                               |
| `source_runtime` | Must match the runtime's registered identity. A runtime cannot claim to be another runtime.        |
| `intent_id`      | Null is only permitted for `kernel.ready`. All other events MUST carry a non-null `intent_id`.    |
| `correlation_id` | Propagated from the originating user request. All events in one user interaction share one `correlation_id`. |
| `causation_id`   | The `event_id` of the direct cause. For the first event in a chain (e.g., `intent.created`), `causation_id` is `null`. |

## 3. Canonical Event Vocabulary

### 3.1 `intent` Namespace

Events emitted by the Kernel when an Intent Object's state changes.

| Event Type                   | Source    | Emitted When                                                                    |
|------------------------------|-----------|---------------------------------------------------------------------------------|
| `intent.created`             | Kernel    | A new Intent Object has been created and persisted.                             |
| `intent.planned`             | Kernel    | The Planner has attached a plan; intent transitions to `PLANNED`.               |
| `intent.executing`           | Kernel    | Intent transitions to `EXECUTING`; Execution Runtime has been invoked.          |
| `intent.verifying`           | Kernel    | Execution reported complete; intent transitions to `VERIFYING`.                 |
| `intent.completed`           | Kernel    | Verification passed; intent transitions to `COMPLETED`.                         |
| `intent.stewarded`           | Kernel    | User authorized stewardship; intent transitions to `STEWARDED`.                 |
| `intent.archived`            | Kernel    | Intent transitions to `ARCHIVED`; lifecycle permanently ended.                  |
| `intent.condition_changed`   | Kernel    | Operational condition changed (e.g., `HEALTHY → RETRYING`). Payload: `{ prior_condition, new_condition }`. |

### 3.2 `world` Namespace

| Event Type      | Source              | Emitted When                                                                                        |
|-----------------|---------------------|-----------------------------------------------------------------------------------------------------|
| `world.changed` | ObservationRuntime  | A qualifying real-world signal has been detected and normalized. **Only the Observation Runtime may emit this event.** |

**`world.changed` payload MUST include:**

```json
{
  "source": "string (calendar | price_feed | email | sms | webhook | document | location | weather)",
  "signal_type": "string (e.g. 'document_expiring', 'price_changed', 'bill_cycle_started')",
  "normalized_data": "object (signal-type-specific normalized data)",
  "observed_at": "string (ISO8601 UTC)",
  "confidence": "number (0.0 to 1.0 inclusive)",
  "raw_source_ref": "string or null (optional opaque reference to original source record)"
}
```

### 3.3 `execution` Namespace

Events emitted by the Execution Runtime.

| Event Type              | Source           | Emitted When                                                                         |
|-------------------------|------------------|--------------------------------------------------------------------------------------|
| `execution.started`     | ExecutionRuntime | Execution has begun; the real-world action is being initiated.                       |
| `execution.completed`   | ExecutionRuntime | Execution has finished. Payload: `ExecutionResult` (see ABI_v1 §3).                 |
| `execution.failed`      | ExecutionRuntime | Execution has failed. Payload: `{ error_code, error_message, attempt }`.            |
| `execution.retrying`    | ExecutionRuntime | Execution failed and a retry is being initiated. Payload: `{ attempt, next_attempt_at }`. |

### 3.4 `verification` Namespace

Events emitted by the Verification Runtime.

| Event Type                  | Source                | Emitted When                                                                  |
|-----------------------------|-----------------------|-------------------------------------------------------------------------------|
| `verification.started`      | VerificationRuntime   | Verification has begun.                                                       |
| `verification.completed`    | VerificationRuntime   | Verification finished. Payload: `VerificationResult` (see VERIFICATION_SPEC_v1 §3). |
| `verification.failed`       | VerificationRuntime   | Verification failed. Payload: `{ method, attempt, failure_reason }`.          |

### 3.5 `policy` Namespace

Events emitted by the Kernel's Policy Engine.

| Event Type           | Source  | Emitted When                                                                             |
|----------------------|---------|------------------------------------------------------------------------------------------|
| `policy.created`     | Kernel  | A new policy has been written by the user.                                               |
| `policy.updated`     | Kernel  | A new policy version has been written; the prior version is retained.                   |
| `policy.retired`     | Kernel  | A policy has been retired by the user.                                                   |
| `policy.evaluated`   | Kernel  | The Policy Engine has evaluated policy for an intent. Payload: `{ policy_id, policy_version, result: 'approved' | 'escalated' | 'denied' }`. |
| `policy.violated`    | Kernel  | An action was attempted that violated an applicable policy. Payload: `{ violation_type, policy_id, action_attempted }`. |

### 3.6 `stewardship` Namespace

Events emitted by the Stewardship Runtime.

| Event Type                  | Source               | Emitted When                                                                           |
|-----------------------------|----------------------|----------------------------------------------------------------------------------------|
| `stewardship.triggered`     | StewardshipRuntime   | A trigger condition was met for a stewarded intent; execution has been initiated.      |
| `stewardship.escalated`     | StewardshipRuntime   | A stewarded intent cannot be automatically recovered; user action is required.         |
| `stewardship.recovered`     | StewardshipRuntime   | A previously escalated or blocked intent has been resolved; normal operation resumed.  |

### 3.7 `learning` Namespace

Events emitted by the Learning Runtime.

| Event Type                      | Source           | Emitted When                                                                                    |
|---------------------------------|------------------|-------------------------------------------------------------------------------------------------|
| `learning.suggestion_created`   | LearningRuntime  | The Learning Runtime has produced a policy suggestion based on observed history.                |
| `learning.suggestion_approved`  | Kernel           | The user has approved a learning suggestion; policy has been updated.                           |
| `learning.suggestion_rejected`  | Kernel           | The user has rejected a learning suggestion; no policy change occurred.                         |

### 3.8 `kernel` Namespace

| Event Type                  | Source  | Emitted When                                                                                  |
|-----------------------------|---------|-----------------------------------------------------------------------------------------------|
| `kernel.ready`              | Kernel  | The kernel has completed boot and all runtimes are registered. `intent_id = null`.            |
| `kernel.lifecycle_violation`| Kernel  | An illegal lifecycle transition was attempted. Payload: see LIFECYCLE_SPEC_v1 §7.            |

## 4. Closed Vocabulary Rule

1. The event vocabulary defined in §3 is exhaustive and closed.
2. No runtime may emit an event whose `event_type` is not in §3.
3. Any event with an unrecognized `event_type` MUST be rejected by the event bus with `EVENT_UNKNOWN_TYPE`.
4. Addition of any new event type requires a MINOR version increment of this document and a corresponding entry in `CHANGELOG.md`.
5. Removal or rename of an existing event type requires a MAJOR version increment.
6. Runtimes MUST NOT define private or internal event types outside this vocabulary. Internal state transitions that do not require inter-runtime communication MUST remain internal and MUST NOT be expressed as events.

---

## 5. Event Immutability

1. An emitted event is a fact. Once written to the event store, it MUST NOT be modified or retracted.
2. Corrections to incorrect events are expressed by emitting a new event that supersedes the prior one. The superseding event MUST reference the incorrect event's `event_id` in `causation_id` and include a `supersedes` field in `payload`.
3. The event store is append-only. Storage engines that support deletion MUST NOT delete event records.

---

## 6. Forbidden Namespaces for Events

The following strings are capability domain identifiers. They MUST NOT be used as event namespaces. Any event whose `event_type` begins with one of these prefixes MUST be rejected by the event bus with `EVENT_NAMESPACE_FORBIDDEN`.

| Forbidden Namespace Prefix |
|---------------------------|
| `banking.*`               |
| `finance.*`               |
| `flight.*`                |
| `food.*`                  |
| `government.*`            |
| `healthcare.*`            |
| `hotel.*`                 |
| `shopping.*`              |
| `ticketing.*`             |
| `transport.*`             |
| `travel.*`                |

These strings identify capability domains within the `capability` field of an Intent Object. They are not event namespaces and conflating them with event namespaces is a design violation.

## 7. Versioning

| Increment | Criteria                                                                                                  |
|-----------|-----------------------------------------------------------------------------------------------------------|
| PATCH     | Non-normative clarifications. No change to envelope schema, event types, or payload definitions.          |
| MINOR     | Addition of new event types. Existing events unchanged. Existing consumers may ignore unknown event types. |
| MAJOR     | Removal or rename of event types, change to envelope schema required fields, change to forbidden namespaces. |

The current version of this document is **1.0.0**. All changes are recorded in `CHANGELOG.md`.
